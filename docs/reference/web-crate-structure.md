# Web crate structure

`crates/ersatzrs-web` owns the HTTP process, protocol endpoints, and the
Leptos admin UI. Its structure follows Rust and Leptos boundaries while keeping
ErsatzTV feature names visible in page modules and parity notes. Do not copy
ErsatzTV's `wwwroot`, Razor, `Pages`, or `Shared` directory shape directly.

```text
crates/ersatzrs-web/
  Cargo.toml
  build.rs
  public/
    bundle.css            # Generated by Stylance.
    images/               # Static image assets served below /public/images.
    js/                   # Hand-written browser JavaScript, when unavoidable.
  src/
    main.rs               # Thin binary entry point.
    lib.rs                # Shared SSR and hydration crate root.
    admin/
      app.rs              # Leptos app root and HTML shell.
      routes.rs           # Leptos route table.
      home.rs             # Admin home page.
      layout/
        mod.rs            # Admin shell and top bar.
        nav.rs            # Navigation drawer and nav groups.
        badges.rs         # Hydrated nav badge islands.
        layout.module.css
      pages/              # Admin page modules grouped by ErsatzTV feature.
      server_fns/         # Leptos server functions grouped by admin feature.
      ui/                 # Reusable admin UI primitives.
      style/              # Global admin CSS modules.
    api/                  # Plain axum admin APIs that are not Leptos server fns.
    host/                 # Runtime bootstrap, config, state, routing, tasks.
    transport/            # IPTV, HLS, HDHomeRun, and other protocol surfaces.
```

## Boundaries

- `host` is server-runtime only. It owns startup checks, database/bootstrap
  state, Leptos configuration, top-level axum routing, and background tasks.
- `transport` is for non-admin protocol surfaces such as IPTV, HLS, and
  HDHomeRun. Preserve public URL shapes and ErsatzTV protocol contracts here.
- `api` is for plain axum HTTP APIs used by the admin UI, such as multipart
  upload endpoints.
- `admin` is for Leptos UI. Page module names should stay close to ErsatzTV
  feature names, but the module layout should follow Rust and Leptos concerns.
- `admin/server_fns` contains Leptos `#[server]` functions. These are part of
  the admin UI boundary, not general HTTP transport.
- `admin/ui` contains reusable UI primitives only. Feature-specific components
  belong beside their page module.

Generated Leptos hydration assets are not stored under `public/js`; they are
built into the configured `site-root` and served as `/pkg`. For local
interactive admin work, install `cargo-leptos` and use `./run.sh dev` or
`./run.sh serve`. These commands keep the native server and WASM hydration
bundle on one build path. A separate `cargo leptos build` followed by
`cargo run` can mix server-function identifiers or asset names and leave the
rendered UI unresponsive. Use `public/js` only for hand-written JavaScript that
cannot reasonably live in a Leptos island.
