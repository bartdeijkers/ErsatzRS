# HTTP endpoint reference

The default base URL is `http://<ersatzrs-host>:8409`. The configured listen
address can change the port.

## User-facing endpoints

| Path | Purpose |
|---|---|
| `/` | Admin UI |
| `/healthz` | Lightweight readiness probe |
| `/iptv/channels.m3u` | M3U channel playlist |
| `/iptv/xmltv.xml` | XMLTV guide |
| `/iptv/channel/<number>.m3u8` | HLS channel stream |
| `/iptv/channel/<number>.ts` | MPEG-TS channel stream |

Use the public host name or LAN address in requests that generate playlists.
ErsatzRS derives absolute guide, logo, and stream URLs from the incoming
request.

## HDHomeRun-compatible endpoints

| Path | Purpose |
|---|---|
| `/discover.json` | Device discovery metadata |
| `/device.xml` | Device description |
| `/lineup_status.json` | Lineup scan status |
| `/lineup.json` | Channel lineup |

The server also participates in HDHomeRun UDP discovery on the local network.
HTTP endpoints remain usable when multicast or broadcast discovery does not
cross a subnet.

## Stream selection

The channel playlist selects the appropriate public stream URL from channel and
FFmpeg settings. Direct requests can use the file extension to select the main
delivery family:

- `.m3u8` requests HLS;
- `.ts` requests MPEG-TS.

Additional query parameters are implementation and troubleshooting controls.
Prefer the URLs generated by `/iptv/channels.m3u` for normal client setup.

The documented orientation-preserving troubleshooting override is:

```text
/iptv/channel/<number>.m3u8?mode=segmenter-fmp4
```

It selects HLS with fragmented MP4 segments. Other `mode` values are internal
pipeline controls and are not stable client configuration.

## IPTV authentication

IPTV routes are open when no JWT signing key is configured. When
`JWT__IssuerSigningKey` is set, all IPTV routes except logos require a valid
HS256 JWT with an `exp` claim.

Supply the token through either:

```text
Authorization: Bearer <jwt>
```

or:

```text
?access_token=<jwt>
```

When the M3U request uses `access_token`, ErsatzRS propagates it into the XMLTV,
logo, HLS, segment, and MPEG-TS URLs it generates. Query-string tokens can
appear in client history and proxy logs; use bearer authentication where the
client supports it.

## Readiness behavior

`GET /healthz` returns:

| Status | Meaning |
|---|---|
| `200 OK` | Database startup and FFmpeg runtime checks are ready |
| `503 Service Unavailable` | A startup or FFmpeg readiness requirement failed |

For detailed results, use **Support** -> **Health Checks** in the admin UI or the
`ersatzrs-healthcheck` binary included in release bundles.

## Internal endpoints

Paths under `/api/`, `/ffmpeg/`, `/iptv/session/`, and `/iptv/hls-direct/` are
used by the admin UI or generated stream pipelines. They are not stable
operator APIs. Use the documented user-facing endpoints instead of constructing
internal URLs.
