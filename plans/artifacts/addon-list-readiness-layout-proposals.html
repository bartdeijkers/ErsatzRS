Add-on list design study · 2026-08-27

Publication readiness without an obstructing page-wide aside

All three proposals restore the collection as the first page-level object, keep publication state in normal document flow, group repeated blockers, and preserve one explicit action for the current state. Proposal A is the recommended balance for frequent review work.

Shared implementation contract

Semantics and accessibility

  • Use a page header for collection identity, a labelled section for readiness, and a nav only for the three workflow steps.
  • No sticky or fixed readiness surface; keyboard focus cannot be obscured by publication chrome.
  • Keep native buttons, links and details semantics, visible focus, 44px primary targets, and live status only for state changes.

Responsive and localization

  • Reflow at 320 CSS pixels without page-level horizontal scrolling.
  • Allow long translated labels and blocker text to wrap; never depend on single-line metrics.
  • At intermediate widths, reduce columns before hiding supporting copy.

State behavior

  • Loading retains a stable readiness section with aria-busy; errors use a recoverable alert in the same region.
  • Blocked, ready, preparing, publishing and published states change the heading, status and sole primary action without moving the collection header.
  • No-JS keeps native Save, Prepare and Publish forms in the same decision region.

Implementation map

  • Reuse the current publication-readiness signals and actions inside AddonMediaListEditorIsland; change composition, not server contracts.
  • Keep grouped blockers and item anchors. Extend the shared Button family only if production adoption is chosen.
  • Verify dark/light themes, 320/390/intermediate/wide widths, 200% zoom, keyboard order, long localization and matched SSR/WASM hydration.
