Critical review of the current choice

These are design risks to validate, not claims about operator behavior. They explain why the baseline should not become the implementation spec unchanged.

Re-opened assumptions
Drawer inside drawer

Search, filters, logic outline, inspector, rule editor, and help disclosures create too many simultaneous layers.

Mode surprise

Opening Logic makes Quick controls read-only. That state change is safe for data, but difficult to predict.

Tree by default

A tree communicates depth, but adds navigation and keyboard cost when most queries may only need ALL, ANY, and NONE groups.

Two jobs on one route

Finding media and authoring a durable collection overlap, but do not necessarily need the same information density or save model.

Recommended product shape

Keep global /search results-first with Variant 4A’s small filter drawer. “Create smart collection” carries the canonical query into Variant 4E’s dedicated composer. Use Variant 4C’s ALL/ANY/NONE group cards as the default editor; open a 4B-style focus view only for genuinely nested child groups. Do not make the baseline’s nested drawer the production default.

Interaction contract

  • Search terms, active-filter count, and Clear remain visible when filters close.
  • The route handoff preserves the exact query and returns to the same results state.
  • Only one group is open for editing at a time in production.

Cognition and accessibility

  • Use short labels, familiar controls, and one primary action per region.
  • Disclosures expose one clearly related content region and work with Enter/Space.
  • At 320 CSS pixels, sticky navigation becomes static and all editors stack.

Implementation boundary

  • One typed AST drives search, chips, group cards, preview, URL, and saved collection.
  • SSR renders query summary and results; a narrow island owns AST editing and focus.
  • Arbitrary nesting uses focus mode rather than recursively indented cards.

References used for this iteration

  • W3C cognitive accessibility: clear content — short sentences, small text chunks, whitespace, and unambiguous formatting.
  • W3C cognitive accessibility: clear controls — standard, recognizable controls with clear purpose.
  • WAI-ARIA APG disclosure pattern — concise show/hide control, visible state, and Enter/Space behavior.
  • U.S. Web Design System search — persistent search terms, explicit submit, and advanced search kept out of the default path.
  • Carbon filtering pattern — active-filter count and clearing without reopening hidden filters.
  • WCAG 2.2 Reflow — no two-dimensional scrolling at 320 CSS pixels and caution with sticky content.
  • Algolia InstantSearch via the retained Context7 review — one UI-state contract for refinements, reset, pagination, rendering, and URL routing; conceptual reference only.
